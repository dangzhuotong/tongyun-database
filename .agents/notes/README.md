# Agent Notes（设计记录）

记录影响本仓库的决定或提案：**为什么这么做、放弃了什么**——代码和文档承载不了的部分。

## 什么时候记

遇到设计与界面实现上的关键取舍，或是权衡后否决的诱人方案时记录，避免后续重复走弯路。

## 目录 = 状态

路径：`{状态}/yyyy-mm-dd-主题.md`，状态变了就把文件挪到对应目录。

- `proposed/`：提案，实现前评审；还没做（或只做了一部分）。
- `implemented/`：已上线。内容要跟实际实现保持一致（路径、命名变了同步改）。
- `rejected/`：考虑过但否了。只在它能防止一个诱人的错误时保留，否则删掉。
- `archived/`：冻结的历史记录，不再改，也不当现行依据。

## 写法

每篇写清：背景、决定、备选方案及为什么不选、后果、需要的验证。互相引用用相对链接。

长期、跨模块的架构决定写 ADR（`docs/decisions/`）；一次性的实现取舍写这里。

目录分状态的做法参考 deepseek-harness（MIT）。
