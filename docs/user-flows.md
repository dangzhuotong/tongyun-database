# 用户主流程

## 人操作

启动 → 选择表 → 查看最多 1000 行 → 按主键下一页 / 编写只读查询（可取消；结果可在本地按任意列筛选，并按表头对数字、日期或文本排序）→ 查询标签各自保存 SQL，刷新后恢复标签与 SQL、不恢复结果 → 从表浏览选择记录 → 填写 JSON 修改字段 → 生成计划 → 检查字段差异、正向 SQL 和回滚 SQL/参数 → 确认或取消 → 执行结果与时间线 → 必要时再次确认并回滚。

查询失败保留输入和上一份结果；预览和执行失败保留当前计划。数据变化时重新查询、重新预览；不能强制套用旧快照。

## 外部 Agent

读取本机 endpoint 与令牌 → 发现能力 → 携带 actor/task → 读取 schema → 发起只读查询或分页 → 准备更新计划 → 显式读取计划 → 按用户已授权范围提供 digest 执行 → 读取结果；同 task 的计划出现在 UI 中。

当前生产连接强制只读，非生产变更由连接 allowWrites 与具体计划指纹约束。不能把 Agent 自报 actor、计划 digest 当作真实身份或用户授权。MCP 即使打开写工具也不回传 digest，执行指纹须由审阅过该计划的人另行提供。

## 网络连接

新建连接 → 选择 MySQL/Redis、环境、TLS 和凭据 → 默认只读保存 → 选择连接并读取/测试。MySQL 按表加载结构并分页；Redis 输入匹配模式 SCAN，选 Key 查看值、TTL、内存，选择对应编辑/TTL/删除动作后生成计划。

网络变更：确认后先持久化意图，再执行目标操作并登记结果。结果未知时 UI 禁止继续执行该计划，保留原值和恢复材料供核查；尚未实现自动核查未知结果的入口。
